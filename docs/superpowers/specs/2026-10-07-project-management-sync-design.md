# 云效 / TAPD 任务同步设计

日期：2026-10-07
状态：已于 2026-10-07 最终批准规格及全部推荐；进入详细实现计划阶段，未开始实现。

## 1. 目标与已确认需求

在现有 DSH 任务列表中接入云效 Projex 和 TAPD 官方公有云，让用户把指定范围的远端任务同步到本地，继续使用现有会话启动、完成和 Worktree 功能，并将本地变化同步回原平台。

用户已明确：

- 首期同时支持云效和 TAPD，接口边界允许后续扩展其他平台。
- 按项目及自定义条件筛选任务，支持负责人、工作项类型、迭代、状态。
- 全部手动触发，不定时运行、不用 Webhook、不在保存本地编辑后自动回写。
- 只有一个「同步」按钮，一次操作拉取远端并按变化情况进行必要回写。
- 保存每端当前更新时间以及上次成功同步时的更新时间，分别判断两端是否改变，不比较两端谁的时钟更晚。
- 只有一端改变时，该端覆盖另一端的同步字段。
- 两端都改变时，标题、描述等其他同步信息取远端，整个任务状态字段取本地并回写远端。
- 保持任务列表现有布局、启动流程和本地执行配置。
- 已确认凭据通过宿主环境变量提供，界面填写变量名而不是保存密钥。

验收成功意味着：实际平台任务能按规则导入，重复同步不重复建单，五种变化分支结果符合规则，失败和并发编辑不丢失待同步修改，原有任务功能不回归。

## 2. 范围与非目标

### 首期范围

- 云效 Projex 工作项；TAPD 需求、缺陷、任务，各类型按配置启用。
- 多连接、多项目同步规则；一个按钮同步所有启用连接和规则。
- 同步标题、描述、状态；优先级、标签、故事点仅在该平台类型支持且用户配置映射时纳入。
- 筛选、项目级状态映射、默认本地工作区关联、来源信息和逐项错误报告。
- 兼容已有 SQLite 数据库，原有本地任务无需外部关联。

### 不做

- 本地独立任务自动创建为远端工作项。
- 自动轮询、Webhook、单独上传按钮、单独拉取按钮。
- 删除传播、评论、附件、工时、自定义字段通用编辑、父子关系同步。
- 私有部署平台或任意第三方 API 地址。
- 变更版本号、打 tag、推送或发布 npm。

本地没有远端关联的任务不参加同步。本地删除已导入任务不会删除远端；它之后仍符合筛选时会重新导入。远端删除、归档导致不可读取、或权限撤销时，保留本地任务及关联，提示具体错误，不自动删除或重新建远端任务。

## 3. 方案选择与架构

采用现有插件内的「平台适配器 + 共用同步引擎 + 同步基准记录」。

未采用两个平台各自完整实现：冲突逻辑容易分叉，维护重复。未采用外部自动化服务中转：需要额外部署，不符合直接在任务列表内操作的目标。

### 单元职责

1. **平台适配器**：持有宿主侧认证；发现项目、成员、类型、迭代、状态和字段能力；分页查询；按 ID 取详情；更新允许的业务字段。云效与 TAPD 独立实现，不能包含 UI 或冲突决策。
2. **同步规划器**：纯逻辑；接受本地快照、远端快照、上次基准和映射，输出无变化、导入、拉取、回写或合并计划。
3. **同步执行器**：串行控制单个关联项，分页发现任务，处理限流与错误，执行远端请求和本地版本校验，确认最终结果再推进基准。
4. **同步存储**：保存连接、项目规则、来源关联、基准、执行记录及单项结果；不访问 Harness 自有日志或索引。
5. **DSH 远程服务**：配置及元数据读取、发起同步、查询进度与结果。通过现有 DSH 服务和 RPC 机制集成，不增加独立 HTTP 服务。
6. **浏览器 UI**：同步设置、一个同步按钮、进度和结果、任务来源信息。复用宿主控件和主题，所有可见文案放入本地化字典。

新代码按职责拆分，不把网络、配置和冲突逻辑继续塞入现有任务面板或 TaskStore。

## 4. 数据模型与迁移

保留现有 tasks、subtasks，采用事务迁移增加同步存储。未知未来 schema 仍拒绝打开。

### 连接

保存连接 ID、平台类型、显示名称、是否启用、认证环境变量名、平台实例身份。

- 云效：个人令牌环境变量名、中心版组织 ID；官方 Region 公有云可选择对应实例模式和官方域名，不开放任意私有地址。
- TAPD：API 用户名与密码各自的环境变量名，官方 api.tapd.cn。
- 不把原始令牌、用户名或密码写入 SQLite、浏览器响应或日志。配置响应只返回变量名及是否已配置。

### 项目同步规则

保存连接 ID、项目 ID、启用状态、负责人/类型/迭代/远端状态筛选、默认本地工作区、按类型划分的字段与状态映射。

各筛选维度之间为 AND，同一维度多个值为 OR；空选择代表该维度不限制。没有项目选择不执行全组织扫描。类型未启用则不导入该类型。

同一远端项目在同一平台实例只有一份有效配置；重复连接或重复规则不得造成同一远端任务多次关联或使用相互矛盾的映射。

### 来源关联与同步基准

每个本地任务首期至多关联一个远端工作项。数据库对本地任务 ID 和平台实例身份/远端项目/工作项类型/远端 ID 两方向分别设唯一约束，而不是凭据名称；轮换凭据不得重新导入重复任务。重复同步去重的承诺以该规范身份为边界；跨项目或类型迁移不自动重绑定。平台能明确证明迁移时，对原关联及新发现项报需处理的来源迁移，不猜测合并或导入第二份；无法识别的迁移是已知限制，能力矩阵需记录 ID 稳定性与可检测性。

存在关联、执行记录或待确认意图的连接/规则不允许物理删除，使用停用；仅无引用的配置可删除。停用不会自动对账或执行远端请求，待确认事实仍保留，重新启用后由下一次手动同步处理。不得级联删除未确认远端写入的证据。

保存：

- 本地任务 ID、连接与规则 ID、远端 ID、类型、编号、原任务链接。
- 最后观察到的远端更新时间/版本标记。
- 上次成功同步时的本地更新时间/版本、远端更新时间/版本。
- 上次成功同步时两端同步字段的规范化快照及远端原始细分状态。
- 上次成功同步时间、最近单项错误。
- 每次远端写入之前，先持久化执行意图，包括关联键、原基准、配置修订、读取到的本地版本/快照、远端版本、计划字段补丁及期望语义、运行所有者和阶段。意图落库失败则不发送请求。超时、回读失败、崩溃或最终本地版本冲突均保留待确认意图，不能伪装成新的成功基准。
- 基准记录同步字段集合、映射和规范化版本；状态或可选字段映射变化先做兼容性检查。新启用字段没有旧基准时不把现有本地默认值当成历史编辑，先按远端初始化该字段并保留其他待同步编辑；禁用字段不再传播。无法安全重解释时停止该项并提示修正，不因配置单独产生远端业务写入。

### 时间与快照

现有 tasks.updatedAt 包含会话、工作区等仅本地变更。因此更新时间作为快速变化信号，最终使用同步字段快照确认是否存在待传播的业务变化。时间精度不足时，字段快照/可用版本标记也能发现变化。仅远端非同步字段改变时同样不发起无意义写入。

同步基准必须指向成功落地后的本地版本和重新读取的远端最终版本，不使用本轮开始时间冒充远端更新时间。

## 5. 字段与状态

### 同步字段

- 必需：独立标题、描述、状态。
- 可选：优先级、标签、故事点；根据工作项能力启用。不存在可靠往返映射的字段不纳入同步。
- 负责人、迭代、类型首期用于筛选与来源元数据，不增加本地编辑字段或自动回写。
- 工作区、Agent、会话 ID、立即发送、Worktree、子任务是本地字段，远端导入和更新不得覆盖。
- 本地实际开始和完成时间继续按现有状态流转生成，不把平台时间戳强行替代为本地执行历史。

仅本地修改时，只回写实际改变且支持的同步字段，不能把整个远端记录序列化后覆盖。

### 标题与描述

现有本地任务保持由描述前 50 字生成标题的行为。已关联外部任务显示和编辑独立标题；仅改状态或启动任务不能重新生成标题。外部任务启动草稿为独立标题加描述（描述为空时仅标题），原本地任务仍按既有描述优先行为；会话创建、Agent、状态绑定和Worktree顺序不变。该启动内容选择已在最终批准门通过。没有适合本地字段的无损内容时，保留原始表示并拒绝有损回写；超出现有字段长度限制时逐项报错，不静默截断并上传。远端富文本以安全方式展示，不注入未净化 HTML。

### 状态映射

按项目及工作项类型加载平台状态候选值。

- 多个远端状态可以映射到同一本地三态：todo、in_progress、done。
- 每一本地状态必须配置确定的回写目标远端状态。
- 最新远端细分状态映射后与本轮同步目标本地状态一致时，保留该细分状态，不将“测试中”无故改成“开发中”。
- 两端都改变且状态有差异时本地优先，即使本地仅修改了非状态业务字段、远端修改了状态，也将状态恢复为本地值；如果本地与最新远端状态映射结果相同，不为改变细分状态而额外写入。
- 未映射状态、无回写目标、平台工作流不允许转换、缺少必填字段、复杂并行工作流不能安全完成时，对该任务报错，不猜测状态或静默标记成功。
- 配置映射变化不是用户业务编辑，必须对现有基准重新解释并检查兼容性，不能因此批量回写错误状态。

## 6. 同步算法

### 变化分支

变化均相对各端上次成功同步基准判断，不比较本地和远端的绝对时间大小。

| 本地业务变化 | 远端业务变化 | 动作 |
| --- | --- | --- |
| 本地没有关联记录 | 新发现远端项 | 新增任务及关联，建立成功基准 |
| 否 | 否 | 跳过，无远端写入 |
| 否 | 是 | 拉取远端同步字段到本地，保留本地配置 |
| 是 | 否 | 将本地改变的同步字段回写远端 |
| 是 | 是 | 非状态同步字段取最新远端；整个状态字段取本地，必要时回写状态，再把合并结果落到本地 |

两端同时变化采用上述任务级规则，不改成按字段各自无冲突合并：即使本地仅修改描述、远端仅修改标题，非状态字段仍按用户要求取远端。

### 一次同步

1. 宿主在SQLite事务中取得数据库级同步运行所有权并创建运行记录、锁定启用配置快照。同一数据库只允许一个同步运行，避免两个Host/实例使用同一file同时远端回写；本地CRUD保持CAS并发。重复点击返回当前运行，不产生第二批操作。租约超时不单独授权新执行器立刻重写：旧代际在请求派发及本地提交前校验，已有意图先对账。详细计划明确租约/心跳和重启接管条件，远端无原子条件时租约不能消除外部在途请求风险。
2. 对各启用规则按固定筛选分页发现远端任务，完整去重。适配器明确固定排序、继续标记与终止条件；TAPD `limit≤200`，超过 `page*limit≤20,000` 的深分页范围采用可支持的固定 ID 排序及串行 cursor。重复/不前进 cursor、接口不支持所需翻页或预算中断都报告发现不完整，不能静默结束为成功。已完整成功的单项仍保留其成功基准。
3. 对该规则所有已关联任务按 ID 获取详情，即使已不再满足筛选条件；筛选只限制新任务发现，不能让完成后的任务失联。关闭连接/规则后停止该范围操作，但保留数据。
4. 单项读取本地版本、远端详情和基准，生成计划。
5. 回写前重新读取远端；发现变化则重新生成计划。若平台提供原子版本条件写入，使用该机制；不假定平台支持。
6. 对本地修改使用现有乐观版本校验。执行期间用户有新编辑，不用旧计划覆盖；保留待同步修改，报告下次重试。
7. 回写仅发送必要字段。回写完成后按 ID 读取最终结果并验证语义。部分成功/超时不推进基准。
8. 对需落地的本地字段和成功基准采用短 SQLite 事务，不跨网络请求保持数据库事务。同一事务校验运行所有者/代际、关联版本及当前本地版本，再写本地字段、基准、意图确认和单项结果；不能只替换旧计划的version重用旧补丁。回读确认以实际写入字段集合逐字段验证，其他远端字段变化保留完整最新观察并重新规划，不能要求整个远端记录等于期望才确认。
9. 最终本地版本校验失败时，保留远端实际写入事实及原始同步基准。下一次先确认旧写入，再以当前本地/远端及原快照计算尚未传播的新编辑；不得把整个最新本地版本直接标为已同步。用户在执行中删除任务时，删除本地任务及子任务仍保留最小脱离关联恢复记录/原任务代际，禁止旧回调触及替代任务；同一规范远端键有未确认意图时阻止重新导入，待对账清结后下一次用户同步可重新导入。未派发的意图在删除后取消，不向远端写入。
10. 记录单项结果；失败不停止其他独立项。结束后汇总并刷新当前任务页。明确连接级认证/额度失败只停止该连接剩余请求，不让每项重复同一失败；其他连接继续。未处理量与发现不完整单独报告，不算未变化。每次请求前检查当前启用状态；配置普通修改对下一轮生效，旧意图只按记录的修订确认，不能以新映射猜测已应用。

### 失败、重试和竞态边界

- 读请求按 Retry-After 和指数退避最多3次尝试（含首次），同一查询串行翻页。默认每请求30秒超时，单次等待上限60秒，整次手动运行30分钟预算；平台特定限制由能力矩阵收窄，不能放宽为无限请求。预算耗尽标为部分完成/未处理，下一次按钮重新发现并对账，不静默遗漏。每连接先串行处理，连接级认证失败停止该连接；未知写入即使预算用完也保留意图。页面/关联扫描按有界分块处理，结果分页默认20上限100，HTTP响应默认上限2MiB，过大响应报具体错误，不继续解析或截断字段。
- 完成运行的摘要及无正文逐项结果保留最近30天且最多100次，按小事务清理；最近成功基准、规范身份及所有未确认/中断写入证据不按年龄清理。意图仅保存实际同步必要字段，不复制完整平台记录到运行日志。关联原始格式也只保存必要同步字段，浏览器来源信息不得包含原始密钥或HTTP详情。
- 写请求超时后先读取远端确认是否已应用，不能盲目重发。工作流副作用不得假定天然幂等。
- 没有平台原子版本条件时，重新读取与写入之间仍有竞态窗口；回读验证降低风险，但无法承诺绝对无冲突。向维护者明确此限制。
- 网络错误、401/403、429、API 业务失败、非法状态和本地版本冲突都给出脱敏的具体原因。
- 关联项的基准只在完整成功后推进，不能因为整批其他任务成功就推进失败项。
- 每次重试先对照现状和已有待确认执行意图，已成功写入不得重复当成新的用户修改形成同步循环。回读等于期望语义时可确认已应用，再以最新本地版本校验落地；明确等于写前值也不证明带工作流副作用的请求未执行后又被撤回。回读既不等于写前也不等于期望、且平台无操作证据时，保持结果未知，不重复原请求、不推进基准、不继续普通回写；同一按钮只重新读取对账，提示查看原平台历史/权限及待确认原因。可见确认依据才能恢复普通规划，不能为了活性猜测成功或失败。
- 插件卸载/Host 停止时先撤销执行器所有权，禁止发新请求和旧回调落库，再中止在途请求，最后关闭数据库。远端可能已接受请求，中止不等于撤销业务写入。运行所有者和每次结果提交均做有效性检查；重启识别旧运行中断，下一次用户点击同步时先对账待确认意图，不自动发起同步，也不永久卡在运行中。

## 7. UI 和远程接口

### 任务列表

## Phase 1：CEO 审查（SELECTIVE EXPANSION）

### 系统审计与前提确认

D1 已确认六项前提，原任务级冲突规则和双平台范围保持不变。不做任何事时，用户仍能复制任务描述到会话，但无法保留来源关联、可靠重复导入及状态对账。痛点不是“同步越多字段越好”，而是把指定平台工作送入正确 DSH 工作区执行，再得到可解释的业务结果。

已读取九个历史提交，重复触及任务编辑器、启动和宽度：8f21e52 曾修正与自动化页宽度不一致，740db3b 与 75326d0 修改弹窗动作和状态。暂无 stash、代码 TODO/FIXME 标记、架构文件或并行源码修改证据；GitHub CLI 无法获取开放 PR，不把本地无差异当远端实时无并发的证明。后续每阶段和交付前重新检查 HEAD 与工作树。

风格参照：store.ts 的参数化 SQL、单调版本与 CAS；attachSubtasks 的批量关联查询；task-title.ts 的独立纯函数及 Unicode 测试。反例：remote.ts passthrough 不提供运行时安全；TaskPanel.tsx 集中大量表单/启动状态，不应继续塞入平台网络和恢复逻辑。已有 CSS token 和 960px 规则可复用，但旧自制按钮/弹窗不是“宿主控件已复用”的证据。

市场搜索找到 [Unito 项目工具双向集成](https://unito.io/integrations/asana-azure-devops/) 作为外部同步类替代的存在性参考，未核实其云效/TAPD 支持、价格或接入时间。[Layer 1] 采用稳定 ID、快照基准、适配器和短事务。[Layer 2] 外部服务可能减少实现工作，但引入部署与数据边界。[Layer 3] DSH 价值是会话/Agent/Worktree 执行上下文，追求通用同步平台会偏离目标。没有证据支持宣称竞争对手不存在或本方案市场领先。

### Step 0D/0F：范围校准、扩展扫描与模式确认

复杂度会超过 8 文件/2 职责，触发检查，但新增网络、恢复和 UI 测试职责是问题固有复杂度。不新增六个 Cordis 服务、通用队列、策略 DSL 或跨插件同步平台，采用一宿主服务和显式模块。SELECTIVE EXPANSION 按 /autoplan 自动确认，保持现有范围，补全故障与体验。

10x 愿景是“从平台工作项到可执行会话及可追溯对账不再靠复制”，不是无限扩展工作项模型。扫描的五项小补齐：成功结果说明字段取舍；配置校验指出具体映射缺口；待确认写入清楚显示；长查询显示发现/处理进度；错误带修复路径和脱敏关联 ID。均复用已有承诺的设置/结果/日志范围，接受。关联退役、诊断文件导出需要新入口与数据模型，延期；自动轮询、Webhook、通用工作流平台拒绝。

### Section 1：架构与四路径

新增功能复用一个数据库及一个 DSH RPC 边界；平台对象不能流进 UI 或 TaskStore 业务判断。无新基础设施，两个适配器不得内置冲突策略。单项远端写入必须以持久化意图为前提；若无法记录意图，则不发送远端请求。

```text
BEFORE  TaskPanel -> TaskFace -> TaskService -> TaskStore(SQLite)
                               \-> Session/Agent/Worktree (existing)
AFTER   TaskPanel + SyncSettings/Results -> validated TaskService
                   |                         |-> existing TaskStore
                   |                         `-> SyncExecutor
                   |                              |-> pure Planner
                   |                              |-> Yunxiao / TAPD adapters -> HTTPS
                   `--- safe DTO <---------------- `-> SyncStore(same DB, short tx)
```

数据库不可用是本地单点，平台故障只影响所属范围。10x 首先触发详情请求/限流，100x 可能拖长手工批次，不能把全部任务详情和原始 HTML保留内存。回退要停用连接保留 schema，旧版本因未来 schema 保护无法直接打开，Section 9 明确安全备份及恢复边界。

```text
配置：有效 env名/项目 -> validation -> metadata -> save revision -> DTO
      missing -> 字段错误无请求；空项目 -> 不扫描；上游错 -> 保留旧配置提示
发现：项目+固定filters -> page/cursor -> normalize+dedup -> import/link
      missing credential -> 范围失败；空结果 -> 0新增仍处理关联；分页错误 -> 不完全
单项：local+remote+baseline -> pending reconciliation? -> planner -> execute -> tx
      无关联 -> 新导入；不存在local -> 删除竞态不再自动创建；不可读remote -> 保留关联
结果：run/items -> safe paged DTO -> progress/result UI
      无run -> 明确not found；空items -> 0项；查询错 -> 可重连，不再触发执行
```

### Section 2：Error & Rescue Registry

这里的错误码是实现合同，不表示已有错误类型。预期错误用有类型的结果，UnexpectedFailure 仅在批次隔离边界收敛并脱敏，不把所有异常都改成“同步失败”。所有条目都需新测试，不能算作现有测试覆盖。

| Method/codepath | 错误类型/触发 | Rescued | 动作 | 用户所见 / 测试 |
| --- | --- | --- | --- | --- |
| saveConnection/saveRule | InvalidConfig / 缺project、非法env名、重复实例项目 | 计划Y | 保存前拒绝 | 指向字段、修复提示 / RPC+DB |
| resolveCredentials | CredentialMissing / 宿主变量未设置 | 计划Y | 不请求，范围失败 | 变量名+Host重启指引，不显示值 / 安全测试 |
| metadata/read/list/detail | AuthDenied /401、403、业务权限失败 | 计划Y | 不重试认证，所属范围/单项失败 | 平台、项目、权限修复 / 两适配器合同 |
| list/detail | ReadTimeout/NetworkFailure/RateLimited | 计划Y | ≤3次读取尝试，Retry-After有限等待 | 进度等待后具体失败 / 假时钟 |
| list parser | InvalidRemoteResponse / 非JSON、缺ID、业务status失败 | 计划Y | 拒绝该页，不伪造空数组 | 不完整发现及具体原因 / 畸形fixture |
| paginator | IncompleteDiscovery / cursor不进展、深分页/预算终止 | 计划Y | 停该查询，范围结果非成功 | 已发现数量+未完成原因 / 多页 |
| getLinkedDetail | RemoteUnavailable / 删除、归档、权限撤销 | 计划Y | 保留任务及关联 | 对应编号，不擅自认定远端删除 / 故障测试 |
| normalize | UnsupportedRepresentation/FieldLimit | 计划Y | 不有损落地/回写 | 字段、长度或格式要求 / 文本边界 |
| plan/transition | MappingIncompatible/WorkflowRejected | 计划Y | 不猜状态；单项失败 | 修正项目类型映射/必填条件 / 工作流 |

| updateRemote | WriteOutcomeUnknown / 超时、断连、部分应用 | 计划Y | 不盲重发，先回读；不确认则留意图 | 待确认不是新成功 / 故障注入 |

### Section 3：安全威胁

平台令牌和 TAPD Basic Auth 扩大宿主出站面，浏览器填写环境变量名也可能成为探测宿主变量存在性的入口。只允许合法变量标识、读取该连接明确引用的值并仅返回 boolean，不能提供任意 env 检索、原值或请求回显。新增 RPC 必须验证对象/类型/长度/枚举/未知字段；已有 passthrough 说明这个责任不能交给静态类型。

| 威胁 | 可能/影响 | 缓解及验证 |
| --- | --- | --- |
| 任意URL/路径拼接导致凭据外发 | 中/高 | 官方入口结构化选择、ID编码、禁止认证请求重定向；host允许列表测试 |
| 错误/日志带密钥或原始内容 | 中/高 | 允许字段结构日志，不记录headers/body/env值；伪密钥遍历DB/响应/日志 |
| 富文本脚本/链接注入 | 中/高 | 原始格式宿主保管，浏览器仅安全文本/净化展示；来源URL allowlist、noopener |
| 参数化RPC变成任意远端更新器 | 中/高 | 严格DTO，只允许配置/同步触发，不接受raw payload/auth/URL |
| 远端内容在会话中诱导模型越权 | 中/高 | 外部任务内容是用户选择执行的数据，标识来源，不提升为系统提示词/自动工具指令；立即发送仍仅用户原配置 |
| 多用户/实例误共享任务或凭据 | 未证实/高 | 保持现有 DSH auth 与 taskList 数据范围；不新增租户模型或暗示细粒度平台权限隔离 |

依赖先用 Node fetch/AbortController/SQLite；若引入 HTML sanitizer，锁定版本和测试且不能自己写正则净化 HTML。权限测试不创造垃圾远端工作项。远端响应全文可能含个人信息，不能把“脱敏”仅理解成令牌替换。

### Section 4：数据及交互边界

逐步追踪配置校验、规范化、持久化和回显：任一步 invalid/too long/unknown mapping 不能变成默认空字段并上传。缺字段、显式空值、不可用字段分开处理；仅启用且可无损往返的字段纳入比较。分页错误不能被归为“零任务”。

```text
input -> validate -> metadata/map revision -> transaction -> safe output
 nil -> reject       upstream error -> retained old config
 empty project -> no scan  incompatible -> no business write
 detail -> presence/format -> snapshot -> plan -> intent -> HTTP -> verify -> CAS tx
              unsafe/limit -> item failure     timeout -> pending   conflict -> pending
```

14个边界：双击、两标签页触发、退出面板、刷新回连、Host停止、元数据迟到、配置运行中保存、任务中途编辑、任务中途删除、筛选外关联、空发现、单项失败、分页中断、重复/越界结果页。分别由宿主单run、持久run查询、客户端请求代际、配置快照、CAS及独立结果处理。关闭页面不取消宿主运行；只停止查询，不触发第二次同步。删除过程中远端已经写入可能不能撤销，必须保留以不泄露任务内容为边界的最小待确认记录。

### Section 5：代码质量

读取当前 store/task-service/remote/TaskPanel/index 后，确定不重写旧任务模型和会话流程。重复风险是两适配器都实现五分支、多个 UI 路径派生外部标题、在 UI 写平台payload；分别放共用纯规划器、明确标题辅助函数、宿主字段补丁编码器。新执行函数按读取/规划/意图/更新/验证/提交拆明步骤，而不是一个分支超过5次的大函数。

命名直接用 SyncPlan/SyncRun/SyncItemResult/SyncAdapter；不用通用 ConnectorFramework 或 YAML策略语言。现有泛 Error 可留旧接口兼容，新同步错误用稳定code+结构化上下文，浏览器翻译。现有注释中标题派生/只发描述及width说明需随对应受影响行为更新，当前无 ASCII 状态图可陈旧；新增 planner/executor 注释嵌入同步和恢复图。

### Section 7：性能

读取每个关联项详情是远端 N+1 式成本，即每个项增加独立请求，本需求下不可能仅凭本地筛选避免。先允许每连接串行、单项常量内存、按页发现/按关联主键分批读取；平台支持可靠批量详情才优化，不凭想象加并发。最慢三路径是长发现/429等待、写后详情验证、关联库存逐项读取；p99目前无实测，不能给伪造毫秒数据。

1000关联项、每请求100ms无重试时，仅一次详情就约100秒，回写还会增加读写请求；这只是算术预算非平台延迟测量。实现计划增加1k和10k模拟数据测试、请求计数、内存和SQLite事务耗时，真实项目记录实际规模与耗时。为 canonical key、rule关联及 run结果分页加索引；元数据只在一次运行/配置加载缓存并带配置revision，不全局缓存权限永不刷新。

### Section 8：可观察性

结果数量已规定，但未规定部分发现和待确认写入的诊断字段，补齐runId/itemKey/connection/rule/phase/errorCode/requestId(if safe)/attempt/duration/counts。每项记录归一化发生变更的字段名和取舍，不默认保存任意平台response正文；原始同步字段仅按业务需要进入受限数据库，不拿日志当第二数据库。用户页就是日一的运行看板，不新增 Prometheus/云监控或自动告警系统。

工作正常的指标是发现完整性、成功/失败/待确认、无变化项远端写请求=0、下一轮无循环。运行失败要可看到规则或单项，而非必须读终端栈。runbook由错误code引导到账号权限、映射、字段格式、网络/限流、并发修改、备份恢复；3周后可用run及intent阶段重建事实，但不能声称能凭脱敏日志重建所有任务正文。

### Section 9：部署、回退与时间约束

迁移增表/索引并更新user_version必须同事务；版本0–4到新schema与失败回滚都测试。迁移前采用SQLite安全备份或停Host复制主库与WAL，不只复制正在写的主库。不开启连接时不运行网络；默认关闭连接相当于功能开关，第一批仅授权测试项目。

```text
BACKUP -> stop Host writer -> build host+client -> install -> start/migrate
       -> verify old tasks+new RPC -> authorized test rules -> enable
failure -> disable sync -> keep new schema+intent -> forward fix
        -> need old binary? stop Host -> archive new DB -> restore full backup
                            (明确新备份后本地编辑会丢，不自动恢复)
```

用户停止/禁用不能撤销远端已接受写入，不自动用旧备份重推远端。Host和client可能不同步：新client遇缺同步方法应提示Host重启且旧CRUD可用，不白屏或自动请求第三方。当前GUI不能通过新服务器验收；现有真实URL刷新、Host重启均需要在实现阶段按授权范围验证。无提交/推送/发版动作，18:00之后也不自动取得许可。

### Section 10：长期轨迹

共享纯规划器和能力矩阵降低平台代码分叉，身份不能依赖环境变量名。远端副作用和数据库升级可逆性较低：整体2/5；停用连接/不回写配置为4/5。明确schema与intent状态机、API样本来源和类型支持矩阵，防止知识只存在本轮对话。

产生两项延后工作：长期关联生命周期、可安全分享诊断导出。不延期恢复/CAS/未知字段/富文本/分页错误，因为它们直接影响数据安全。后续适配器可以实现同接口，但不预先做注册市场、自动同步或通用自定义字段编辑。

### Section 11：设计意图

首屏仍是任务列表：任务内容/独立标题优先、状态次之、来源为轻量补充；设置和结果不抢主导航。首次配置、加载、空项目、状态缺映射、正在运行、部分成功、待确认、刷新后恢复查询必须明确显示，不只说后端会处理。状态变化产生本地执行时间与原平台更新时间要区分命名。

```text
Task list -> Sync settings -> metadata + map validation -> save (no sync)
          -> Sync -> discovering/processing -> success/partial/interrupted
                     `-> leave page -> return/query same run (no new sync)
          -> edit external task -> title/description + source facts -> save local only
```

已有QA显示焦点和窄屏问题，新增设置弹窗必须使用宿主真正组件、键盘焦点闭环，新增来源不可再挤内容列。无需新字体/营销卡片；全局主题优先于技能里的通用营销审美。深度7维审查在下一阶段完成，当前不得称视觉验收已通过。

- 旧任务列表整体重设计/相邻Worktree环境修复：不借同步规格改其他插件，单独跟踪。
- 版本/提交/推送/npm：本轮未授权，非审查产物。
