# DSH 任务列表

[English](README.md) | 中文

DeepSeek Harness 的原生任务列表：独立 SQLite 存储，搜索与分页在宿主侧完成，可一键启动与完成。

DeepSeek Harness Web 的原生任务列表插件：侧边栏增加「任务列表」，以单列列表显示任务。页面沿用内置「自动化任务」页的版式：内容区居中、最宽 960px，左右留白随面板宽度伸缩（`clamp(24px, 4vw, 48px)`），在两页之间切换时列表宽度不变。每行展示任务内容（描述），后面是固定宽度的状态和工作区，超出部分省略；右侧为「启动」/「完成」按钮，绑定的会话 ID 和创建时间不在列表里显示（编辑弹窗内仍可看到创建、开始和完成时间）。工具栏提供状态筛选、工作区筛选、搜索框与「搜索」「刷新」按钮，任务较多时按页加载（每页 10/20/50/100 条，默认 20 条），分页、筛选与搜索都在宿主侧完成。

任务仍可保存子任务数据，数据库表和远程接口都保留，但当前版本暂时不在任务行和编辑弹窗里显示或编辑子任务，后续版本会恢复。

在对话输入框里按 `Ctrl+S`（macOS 为 `Cmd+S`）可把当前未发送的文字和已添加的文件、图片附件一起存成任务；即使文件仍在宿主后台上传，也会保存浏览器持有的原始字节，不只保存临时上传引用。只有附件没有文字也能创建任务，标题取内容（含附件名）前 50 字，优先级默认「普通」，不关联工作区和会话。成功后清空已保存的文字和附件，输入框工具行右侧显示「已创建任务：…」，几秒后自动消失，全程不弹对话框。文字与附件都为空时不创建任务，只提示「输入框没有文字或附件」；附件读取或任务创建失败会保留文字和附件并显示原因。「存为任务」按钮不再显示，仅保留快捷键操作。

新建与编辑共用同一个弹窗：不再填写标题（保存时自动取内容前 50 字作为标题），内容为必填项。字段自上而下为：内容整行 → 工作区、Agent → 「立即发送」和「使用 Worktree」同一行（先「立即发送」后「使用 Worktree」）→ 优先级、状态 → 标签、故事点 → 底部的只读信息区（会话 ID，编辑时还有创建时间、开始时间、完成时间）。状态在新建和编辑时都是可改的普通字段：新建默认「待办」，任务可在「待办」「进行中」「已完成」之间随时切换——改为「进行中」记录开始时间，改为「已完成」记录完成时间，改回「待办」会清空完成时间并保留此前的开始时间。其余只读项与上方字段一样呈现为字段样式，只是不可编辑：会话 ID 在启动时自动绑定，时间戳随状态流转更新。编辑弹窗右上角并排提供「启动」和「完成」两个按钮，点击后先保存当前编辑，再执行对应操作，不需要先保存再回列表点击。「启动」在任何状态下都能用：进行中或已完成的任务可以再次启动，会为该任务新建一个会话并重新绑定；「完成」只在任务还未「已完成」时可用。弹窗固定高度、自上而下分三行：标题栏固定在顶部（编辑时右侧是「启动」/「完成」按钮，不随内容滚动），中间字段区可滚动，底部固定「取消」「保存」按钮；窗口窄于 560px 时回退为每行一个字段。

任务内容使用 **Lexical 富文本编辑器**，工具栏按撤销/重做、段落、文字格式和列表分组，复用宿主按钮与悬浮提示，选中格式会高亮；下方提供正文留白、字数提示和带文件类型图标的附件卡片，随宿主浅色/深色主题切换。支持加粗、斜体、下划线、标题、列表和撤销/重做；粘贴网页或 Word 正文时保留常用文字格式、链接和表格（不保留字体、颜色、分页和完整 Office 排版）。粘贴 HTML 会经过安全清洗，脚本、事件和危险链接不会保存。图片文件可以粘贴或拖入作为附件；只有外部网址或 Word 内部路径的图片不会自动下载，并会提示手动添加。复制文档正文与添加文档文件是两种操作，附件不会自动解析成正文。

正文按编辑器无关的结构化 JSON 保存，纯文本投影用于搜索和自动标题。附件引用在正文中，实际字节存入同一个独立 SQLite 库的附件表；任务列表不加载附件字节。支持添加、下载和移除附件，最多 8 个、单个 10 MiB、总计 20 MiB。移除附件后保存会清理字节，删除任务也会清理附件。启动任务时，文字格式转换为 Markdown，附件恢复到宿主输入框；「立即发送」同时发送文字与附件。对话输入框的 Ctrl+S 也会持久保存当前附件，失败保留输入，异步保存期间新增的文字不会被清空。

任务保存在插件独立的 SQLite 文件，不直接修改 Harness 会话日志或查询索引。

## 环境要求

- DeepSeek Harness 0.2.0-rc.1 或更新版本，且 Web 端提供工作区控制器
- Web profile
- Node.js `^22.19.0` 或 `>=24.0.0`（使用 `node:sqlite`）
- 启用「使用 Worktree」时，Web profile 还需安装并启用 `@guowenzhang/dsh-worktree` 1.x

## 从本目录构建安装

```powershell
cd C:\02-codespace\DeepSeek\dsh-task-list
npm ci
npm run typecheck
npm test
npm run build
dsh plugin --profile web add 'link:C:/02-codespace/DeepSeek/dsh-task-list'
```

重启 `dsh web` 并刷新浏览器，然后点击侧边栏「任务列表」。浏览器代码修改后重建并刷新；宿主代码修改后必须重载插件或重启 Host。保存富文本前会检查宿主是否支持附件存储，并核对返回正文与可读取的附件记录；旧宿主会报错并保留输入，不再静默丢弃附件。只有图片文件名而没有保存字节的历史任务无法自动恢复图片，需要重新添加。卸载命令：`dsh plugin --profile web remove @guowenzhang/dsh-task-list`。卸载不会删除任务数据。

默认数据库路径是 `<DSH_HOME>/task-list/tasks.sqlite`（通常为 `~/.dsh/task-list/tasks.sqlite`）。Cordis 配置可通过 `file` 指定其他绝对路径。插件启用 SQLite WAL 模式，任务更新带版本号，过期编辑会被拒绝。运行中备份请使用 SQLite 备份 API 或 `VACUUM INTO`；DSH 停止后复制 `tasks.sqlite` 以及可能存在的 WAL 侧文件。旧版数据库会在启动时自动迁移：v3 之前的库补齐卡片字段与启动选项，v3 的库增加子任务表，v4 及更早的库迁移为 v5，增加富文本 JSON 与附件表。旧内容按纯文本迁移（不解释 HTML），任务版本号和时间不变。升级后必须重启宿主，迁移后的数据库不能由旧版插件打开。

搜索是字面匹配（`%`、`_`、`\` 不当作通配符），会命中标题、内容、会话 ID 以及子任务的内容和会话 ID；分页与筛选同时生效。列表默认按「待办」「进行中」「已完成」分组，组内按更新时间倒序。

任务提供「待办」「进行中」「已完成」三态。第一次转入「进行中」时自动记录实际开始时间；转入「已完成」时记录实际完成时间。重新打开任务会清除完成时间，保留首次开始时间。旧任务的历史时间不会被推测填入。工作区选项取自 Harness 工作区列表；未关联工作区的任务按默认工作区处理（标题为 `default-workspace` 或本地化「默认工作区」的那个，找不到时取列表第一个）；按默认工作区筛选时会一并列出未关联工作区的任务。

任务可设置 Agent、会话 ID、「立即发送」和「使用 Worktree」。「立即发送」默认关闭。点击待办任务的「启动」，会在关联的工作区创建新会话，把任务内容（描述）填入对话输入框，自动绑定新会话 ID，并把状态改为「进行中」；标题由内容前 50 字自动生成，不再重复拼接进发送内容，只有内容为空的旧任务才回退为标题。开启「立即发送」后还会直接发送这段内容。选择 Agent 时会在首条消息前应用对应预设。启用 Worktree 时，通过 `dsh-worktree` 从所选工作区创建独立工作树和会话；任务的工作区字段仍指向原工作区。编辑表单会提示所选工作区尚未初始化 Git，但仍允许先保存任务。若点击启动时发现工作区不是 Git 仓库，会弹窗提供「更换工作区」或「初始化并启动」；弹窗只列出首层文件和目录，支持全选、全不选；勾选的目录及内容进入首次提交，未勾选项加入根目录 `.gitignore`，原有规则会保留。独立的嵌套 Git 仓库不可勾选。确认后会创建 `.git`、首次提交和 Worktree。如果所选目录只是多个仓库的上层目录，通常应改选具体 Git 工作区。任务未关联工作区时会在默认工作区中启动；关联的工作区已被删除时会报错并提示更换。进行中任务显示「完成」按钮，点击后状态改为「已完成」；已完成任务显示只读状态。列表保留这两个快捷操作，编辑弹窗里则可以直接把状态改成三者中的任意一个，其「启动」按钮也能让进行中或已完成的任务再次启动。删除任务会同时删除它的子任务。任务列表不镜像单会话的 `todo/write` 清单。

## 开发

`src/store.ts` 负责 SQLite 表结构、输入校验、搜索、分页和读写；`src/task-service.ts` 通过 DSH 远程服务暴露宿主操作；`src/client/` 注册原生面板，并从会话目录读取可关联的会话。数据库发现未知表或未来版本时会拒绝打开，不覆盖数据。行为测试使用临时 SQLite 文件。

```powershell
npm run typecheck
npm test
npm run build
```
